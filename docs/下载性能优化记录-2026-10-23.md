# 下载性能优化记录（2026-10-23）

## 调整

| 环节 | 调整前 | 调整后 |
| --- | --- | --- |
| 下载排队 | 所有书共用一个串行队列 | 按域名排队，不同网站并行，后台最多三个网站 |
| 请求间隔 | 每次响应后固定等待 700 ms | 同站请求开始间隔至少 700 ms，响应立即交给解析和保存 |
| 阅读 | 与后台下载同队列等待 | 优先于排队的后台请求，保留一个请求容量；已有同章任务会提升优先级 |
| 连接 | 每次请求重新创建 HTTP 客户端 | 共享连接池，连接空闲 90 秒后回收；新连接仍校验 DNS，跳转继续校验 URL |
| 暂停 | 已排队的章节仍可能发出请求 | 撤回未发出的后台请求，保留已缓存章节；续传跳过缓存 |
| 单站失败 | 慢请求阻挡其他所有网站 | 仅占用自身网站及一个全局容量；429/503 单站退避，保留原有重试上限 |

全局最多四个请求，其中后台最多三个；同一域名仍同时只发一个请求。不会中断已经发出的原生 HTTP 来腾出容量，也不会保存不完整的章节分页正文。

新增测试覆盖跨站并行、同站限速、阅读优先和同章请求共享、容量上限、暂停撤回排队请求、原生请求取消后仍占用容量、单站限流退避、重试与续传。

原生 HTTP 测试通过本地隔离服务证明：一次重定向和两次正文读取使用同一条 TCP 连接，DNS 解析一次；池化客户端仍拒绝内网跳转，DNS 空结果和混入内网地址的结果仍被拒绝。

固定条件的调度测试：两个网站各三个网页，每个响应耗时 200 ms。旧策略按顺序累计为 5400 ms，新策略测试完成于 1600 ms。该结果仅用于验证排队开销，不能直接当作真实网站的提速比例。

## 真实桌面验证

使用独立书库和 WebView 资料目录，通过 Playwright 操作打包后的桌面端；实际请求由 Tauri 原生接口发出，没有模拟网络响应。用户书库未参与测试。

测试来源：`www.xf-cn.cc` 和 `www.kvnk.cc`，各取已识别目录的前六章。

1. 两站同时下载：首个原生请求记录的开始时间差为 0 ms，完成时间证明请求重叠。
2. 暂停第一本，第二本继续完成。
3. 暂停状态下进入第一本尚未缓存的第六章，正常展示正文，批量任务保持暂停。
4. 第一本文本缓存停在 2/6；第二本完成后第一本没有继续发出后台请求。
5. 继续第一本后两本均达到 6/6；已缓存正文保持一致，各章入口仅请求一次，保存的第 2 章、37% 阅读位置保持不变。
6. 再进入已缓存章节，没有额外网络请求；无页面 JavaScript 错误。测试书籍已清理。

合计 12 个真实网页请求，网络阶段约为 171–546 ms；包含暂停、按需阅读、等待及续传的整个操作流程耗时约 7.5 秒。这不是持续下载吞吐量测试，也未据此给出整本书的预计剩余时间。

诊断记录仅在 debug 的隔离测试模式启用。并发写日志已改为整条序列化并加锁写入，避免记录交叉。测试数据位于 `.test-fixtures/online-speed-20261023/data2/`，结果与截图位于同一测试目录；不会在正常书库写入测试日志。
